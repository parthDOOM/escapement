Escapement

A chip that speaks UART, SPI, I2C, CAN, JTAG, ARM SWD and more, with none of them built into the hardware. Firmware schedules every pin change for an exact 40 ns tick. The chip makes that tick, or refuses the change when it is queued. It never runs late.

The one promise

Early or refused, never late

A microcontroller that bit-bangs a protocol is always a little late: an interrupt, a cache miss or a busy loop pushes an edge out, and nobody is told. Escapement separates deciding an edge from making it.

An instruction such as EMIT does not touch the pin. It puts an event into its context's four-entry queue with an absolute deadline taken from the context's timer. A timing unit applies the event on the clock edge whose tick equals that deadline, to the tick.

The check happens when the event is queued. The deadline must be strictly after the commit tick and strictly after the last event already queued. If it is not, the event is refused, the context stops with a fault that names the reason, its pins are released, and the other contexts carry on. A late edge cannot happen, and that is proved formally.

Time is the only thing in hardware

Nothing on the chip knows what UART or I2C is. The silicon offers three kinds of timed event: DRIVE sets pins, EXPECT checks that an input holds a level or arrives at it within a window of up to 127 ticks, and SAMPLE captures one input bit. Everything else is a program in the 256-word program memory.

Because the deadline is absolute, a program can compute it, reuse it and check it. A static analyser, escert, walks every path of a firmware and proves a lower bound on how early each event is queued. The chip measures the same quantity while it runs, so the certificate and the silicon check each other.

The barrel

Four contexts share one pipeline in fixed slots. Context k fetches in every cycle where t mod 4 = k and commits three cycles later. There are no stalls between contexts, so a slow protocol in one context never moves another context's edges. Below are the first 160 ticks of a real run with four protocols at once.

Verification

Every claim is checked twice

Tests show that something works on the cases tried. The properties that matter most are proved for every reachable state instead.

Two models in lockstep

The RTL and an independent Python model of the machine run side by side and are compared on every tick: each commit, every register, every pin, the queues and the memories. Thousands of random programs and every firmware agree with zero mismatches.

A 32-bit execution digest folds every commit, register write and pin change of a run into one word. After a run on silicon, one SPI read compares the chip with the model's prediction.

To check the tests themselves, 28 one-line faults were planted in the RTL. All 28 were caught.

Physical design

The die

Six by four Tiny Tapeout tiles, laid out with LibreLane and OpenROAD on IHP's open 130 nm process. Zoom in until the wires become separate.

Down to the transistors

The close-up is cut straight from the final layout. Green active area and red gate poly form the transistors. Thousands of contacts and vias climb through Metal1 to Metal4, which carry the signals. A standard cell is one row of that structure, 3.78 µm tall.

Only four metal layers can carry signals in a Tiny Tapeout block on this process, and each SRAM blocks three of them over its whole footprint. Routing Metal1 as a signal layer cut global-route overflow from 5,276 to 76, and the final layout ends with 68.

To save power, register banks that are not being written do not see the clock: 68 clock gates cover about 2,600 flip-flops, and each memory is selected only on the cycles that read it.

Power: measure, then cut what dominates

The first netlist used 93% of its busy power while doing nothing, all of it clocking flip-flops and reading memories every cycle. Clock gating, on-demand memory selects and a split hold margin cut every workload by about two thirds.

Figures are from gate-level simulation at the typical corner, with the memory energy counted edge by edge.

Using the chip

Bring it up

  1. Load. Over a four-wire SPI link, write the program memory, the tape and the configuration: which contexts run, where each starts, which pins each owns.

  2. Run. START begins all contexts on the same tick. Each talks to the host through its own two-word mailboxes, for example the bytes a UART should send.

  3. Watch. While it runs, read any context's registers, queue telemetry and checker results, or let the capture unit record every edge into the tape.

  4. Check. After STOP, read the execution digest and compare it with the simulator's prediction for the same program and inputs.

A staged bring-up script for the Tiny Tapeout demo board's RP2350 tests the link, both memories, every pin and every firmware in order, and says what each failure most likely means.

Everything is open: RTL, firmware, assembler, simulator, certificate checker, proofs and the flow configuration.
